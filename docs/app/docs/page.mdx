

# Controlling Serialization

By default RonCS serializes all public fields and properties on a type. However this behavior can be controlled using the `[RonInclude]` and `[RonIgnore]`

<SideBySide>
  <CodeBlock>
    ```cs
    public class User {

      // Will not be serialized.
      [RonExclude]
      public string temporaryNotes;

      // Will be serialized even though it's private.
      [RonInclude]
      private string internalNotes;
    }
    ```
  </CodeBlock>
  <CodeBlock>
    ```rs
    User(
      // note is missing
      // myPrivateNote is included
      internalNotes: "Some string value."
    )
    ```
  </CodeBlock>  
</SideBySide>

### Lists and Dictionaries

Lists and dictionaries can be serialized using the `[RonList]` and `[RonMap]` attributes.

<SideBySide>
  <CodeBlock>
    ```cs
    public class ClassList(string[] values)
      : IEnumerable<string>{
        
        public string[] classes;

        public IEnumerator<string> GetEnumerator(){
          return values;
        }
    }

    public class Student{
      [RonList]
      public ClassList list;
    }

    var value = new Student{
      list = new ClassList(["A", "B"])
    };

    Ron.Serialize(value);
    ```
  </CodeBlock>
  <CodeBlock>
    ```rs
    Student(
      // MyListType is serialized using the 
      // Ron list syntax, instead of
      // serializing it's fields.
      list: ["A", "B"]
    )
    ```
  </CodeBlock>
</SideBySide>

The attribute can also be used on classes.

<SideBySide>
  <CodeBlock>
    ```cs
    [RonList]
    public class ClassList(string[] values)
      : IEnumerable<string> {

      public string[] values = values;

      public IEnumerator<string> GetEnumerator(){
        return values.GetEnumerator();
      }
    }

    var value = new ClassList("A", "B");

    Ron.Serialize(value);
    ```
  </CodeBlock>
  <CodeBlock>
  ```rs
  // Serialized as a plain list.
  ["A", "B"]
  ```
  </CodeBlock>
</SideBySide>

## From and Into

In Rust the From and Into traits can be used to create automatic type conversion between types.

Attributes can be used in C# to enable Ron to automatically convert types when serializing.

For example.

<SideBySide>
  <CodeBlock>
    ```cs
    public class Vector3{
      public float x;
      public float y;
      public float z;

      [RonFrom]
      public static Vector3 From(string source){
        return Vector3.Parse(source);
      }

      [RonInto]
      public string IntoString(string source){
        return this.ToString();
      }
    }

    var value = Ron.Deserialize<Vector3>(
      ronEncodedAsString
    );

    var stringValue = Ron.Deserialize<string>(
      ronEncodedAsVector
    );
    ```
  </CodeBlock>
  <CodeBlock>
    ```cs
    // When deserialized into a vector type
    // it will call Vector3.From(string)
    // To convert to a vector.

    var ron = "\"(1, 2, 3)\""
    Vector3 value = Ron.Deserialize<Vector3>(ron);

    // Will be Vector3(1, 2, 3)
    ```

    ```cs
    // When deserialized as a string
    // Ron will automatically call
    // Vector3.IntoString to perform 
    // the conversion.
    var ron = "Vector3(1, 2, 3)";
    string value = Ron.Deserialize<string>(ron);

    // Will be "(1, 2, 3)"
    ```
  </CodeBlock>
</SideBySide>

## Proxies

Sometimes objects cannot be serialized the same way that they are defined.

A proxy object can be created to serialize such types.

<SideBySide>
  <CodeBlock>
    ```cs
    [RonProxy(typeof(StringVector))]
    public class Point{
      public Vector3 position;
    }
    ```
  </CodeBlock>
  <CodeBlock>
    ```cs
    public class StringVector{
      public string value;

      [RonFrom]
      public static StringVector From(
        Point myCoolClass
      ){
        return new StringVector{
          myCoolClass.value.ToString();
        };
      }

      [RonInto]
      public static Point IntoMyCoolClass(
        StringVector proxy
      ){
        return new Point{
          point = Vector3.Parse(proxy.value);
        }
      }
    }
    ```
  </CodeBlock>  
</SideBySide>
